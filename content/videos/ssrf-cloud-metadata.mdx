## Summary

Server-Side Request Forgery (SSRF): the attacker makes the server send a request on their behalf. The server can reach places the attacker cannot, like internal admin panels or the cloud metadata service at `169.254.169.254`.

In this episode a URL preview feature fetches any address it is given. In the lab, that is enough to read instance metadata. The full writeup has the findings table and the fixes.

<Callout type="defence" title="detect and fix">
  Alert on outbound requests from app servers to `169.254.169.254`. Resolve each destination first, then block private, loopback and link-local addresses before connecting. Require IMDSv2 tokens with a hop limit of 1.
</Callout>
