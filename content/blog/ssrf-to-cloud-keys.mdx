<Responsible>The vulnerable app and fake metadata service below run in Docker on your machine.</Responsible>

## 1. What SSRF is

Server-Side Request Forgery (SSRF): the attacker makes the server send a request on their behalf. The server can reach places the attacker cannot, like internal admin panels or the cloud metadata service.

<Callout type="note">
  Think of it as borrowing the server's network position. The bug is not the request itself. It is trusting a destination the user chose.
</Callout>

## 2. Why the cloud makes it worse

Cloud instances expose a metadata service at `169.254.169.254`. Older configurations (IMDSv1 on AWS) return temporary credentials to any process that asks, with no extra header required.

## 5. Detect and defend

<Callout type="defence" title="checklist">
  - Resolve the hostname, then block private, loopback and link-local IPs before connecting.
  - Enforce IMDSv2 and a hop limit of 1 on every instance.
  - Alert on outbound requests from app servers to `169.254.169.254`.
</Callout>

A minimal allow-list check in Python, run after DNS resolution:

```python
import ipaddress
import socket

def is_safe(host: str) -> bool:
    addr = ipaddress.ip_address(socket.gethostbyname(host))
    return not (addr.is_private or addr.is_loopback or addr.is_link_local or addr.is_reserved)
```
